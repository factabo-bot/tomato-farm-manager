# テスト

養液設計まわりのテスト。ブラウザだけで動く（Node もテストランナーも要らない）。

```powershell
.\test\run.ps1                # 全部
.\test\run.ps1 -Only engine   # 計算エンジンだけ（速い）
.\test\run.ps1 -ShowAll       # 失敗行だけでなく全出力を見る
```

`frontend/` を `test/_work/` にコピーし、**`config.js` の `GAS_URL` を空にしてから**テストする。そのままの `frontend/` を対象にすると、テストが本番のスプレッドシートに書きに行ってしまうため。`_work/` は毎回作り直されるので、中身をいじっても意味がない（`.gitignore` 済み）。

## 中身

| | 内容 |
|---|---|
| `engine/` | 計算エンジン。DOM を持たないので単体で開くだけ |
| `ui/` | 画面。`iframe` で本体を読み、操作して結果を見る |

### engine

| ファイル | 何を見るか |
|---|---|
| `test.html` | 組成・EC・電荷収支・沈殿判定などの基本 |
| `ph-test.html` | pH の帯と原液タンクの pH |
| `cost-balance-test.html` | 肥料コスト、規模の試算、制約付きの組成づくり |
| `acid-test.html` | 中和酸の反映と必要量 |
| `feed-eval-test.html` | 実測からの評価と助言 |
| `property-test.html` | **性質テスト**（下記） |

### ui

`seed*.html` で `localStorage` に状態を作ってから、テストページを開く。同じ `--user-data-dir` で2回 Chrome を起動する必要があるのはこのため。

| ファイル | 何を見るか |
|---|---|
| `tank-split-test.html` | タンクの自動振り分けと沈殿の警告 |
| `recipe-test.html` | 処方の保存と読み込み |
| `solve-test.html` | 逆算の画面 |
| `cost-ui-test.html` | コストの画面、元素を固定した組成づくり |

## 性質テスト（`engine/property-test.html`）

個別のケースを並べるのではなく、**入力を大量に生成して不変条件を確かめる**。実機で出たバグ（Ca が調整対象から漏れていた件）が、個別ケースのテストをすり抜けたことへの対応。

| | 検証 |
|---|---|
| A | 組成づくり 400 パターン。**実装とは別の方法（区間法）で解の有無を判定して突き合わせる** |
| B | 逆算の往復 300 パターン。出した配合を組み立て直して目標に戻るか |
| C | 配合→組成 150 パターン。肥料塩も原水も中性なので電荷は必ず釣り合う |
| D | 中和酸 120 パターン。酸を入れても電荷は釣り合う |
| E | 実測評価 300 パターン。式が定義どおりか、助言が空にならないか |
| F | 中和酸の価数。0.1〜6 meq の全域 |

A が要点。電荷は各イオンの一次和なので、**可動域の端だけ見れば解の有無が判定できる**。これは探索アルゴリズムとは独立した計算なので、探索が解を見落とせば必ず食い違う。

乱数はシード付きなので、失敗したケースは再現できる。

## テストが本当にバグを検出するか

わざと壊して落ちるか見る、を時々やること。テストが増えても、検出できなければ意味がない。

過去に確認した例：

| わざと戻したバグ | 結果 |
|---|---|
| `BALANCE_PRIORITY` から `Ca` を外す | A が落ちる |
| 中和酸で硫酸を1価扱いにする | 46 件落ちる |
| 組成づくりの調整を1周だけにする | **落ちない**（＝そのループが不要だった。実際に削除した） |

3つ目のように、落ちないことが「テストの穴」ではなく「そのコードが要らない」を意味することもある。

## この環境の癖

- **`--window-size` は viewport に反映されない**（390 を指定しても 485 になる）。実機幅の確認は iframe に幅を与えて中を測る
- **`--allow-file-access-from-files` が無いと iframe の中を読めない**。テストが `testing...` のまま止まる
- **`<details>` の開閉が描画に反映されない**（headless Chrome 152 で確認。素の details でも閉じた中身の高さが残る）。折りたたみは `open` 属性で判定するしかなく、**見え方は実機で確認する**
- **hidden 要素は `getBoundingClientRect()` が全ゼロを返す**。レイアウト検査が「中身を見ずに合格」しないよう、可視性（`offsetParent`）を先に確かめる
- **ハッシュだけ変えても iframe はリロードされない**。クエリを変えて別 URL にする
