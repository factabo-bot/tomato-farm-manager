# セットアップ手順

## 端末保存・差分同期の更新（2026-09-21）

1. Apps Scriptエディタのコードを `gas/Code.gs` に貼り替えて保存する。
2. 「デプロイ」→「デプロイを管理」→既存デプロイの編集→「新バージョン」で更新する。URLは維持する。今回の更新で `setup` の再実行は不要。
3. `frontend/` の変更をGitHub Pagesへ公開する。アプリをオンラインで開き、更新後に一度閉じて開き直す。
4. 「今すぐ同期」で取得し、最終同期時刻と記録を確認する。一度取得した画面・直近90日分の記録は端末から表示する。

マスタは初回も同梱データで表示し、取得後に更新する。共有データをまだ取得できていない場合は未取得と表示する。初回取得そのものの通信時間は残る。

送信内容は通信前に端末に保存し、通信中に画面を閉じた場合も次回の同期で再送する。アプリが開いている間は1分間隔、オンライン復帰時、アプリに戻ったときに同期する。閉じている間の自動送信は行わない。ブラウザのサイトデータを消すと未送信データも消えるため、消去前に未送信件数を確認する。

新GASの `action=sync` は作業・散布・生育・気象を一括取得する。初回と同期カーソルの期限切れ時は全量、それ以降は変更・削除のみを返す。更新日時が変わらないシートの直接編集も、内容の指紋で検出する。シート全体を読む処理は残るため、GAS自体の応答時間がゼロになるものではない。GASが旧版の間は既存APIに自動で切り替えて取得するが、差分同期・サーバー側の競合検出は利用できない。

新しい同期で取得した作業・散布・生育の取消と散布の実施操作は、取得時の版を照合する。他の端末やシートで変更されていた場合は未送信欄に理由を表示し、自動で上書きしない。該当操作を取り下げ、同期してから内容を確認する。給液の「1日1行」保存や旧API由来の記録には、この版照合は適用されない。

散布の使用回数は全期間の別キャッシュを使用し、取得日時を表示する。共有先への反映待ちや他端末の未送信記録は、取得済みの回数に含まれない。

## 0-2. 使用回数の管理を追加したとき（2026-09-18）

農薬の使用回数を「その作で何回目か」で数え、資材を選ぶ画面と履歴で見られるようにした。反映するには：

1. Apps Scriptエディタで最新の `gas/Code.gs` に貼り替えて保存
2. **`setup` を実行**（マスタ_資材に4列、マスタ_拠点棟に1列が追加される）
3. マスタ_資材の新しい列に値を入れる（下記）
4. マスタ_拠点棟の「現作の開始日」に定植日を入れる（空なら全期間を数える）

デプロイの更新は要らない。`doGet`/`doPost` のロジックは変えておらず、集計はフロント側で行っているため。

数えるのは3つ：

| 何を | どこから | なぜ |
|---|---|---|
| 本剤の回数 | マスタ_資材「本剤の使用回数」 | その製品を何回まで使えるか |
| 成分の通算 | マスタ_資材「成分と通算回数」 | **別の製品でも同じ成分なら足される**。ここが要 |
| 作用機構 | マスタ_資材「IRACコード」「FRACコード」 | 同じコードが続くと効かなくなる |

**成分の通算が実質の主役**。TPN（クロロタロニル）を含むフォリオゴールド・アミスターオプティフロアブル・ダコニール1000は、どれを使ってもTPNとして通算6回以内になる。剤ごとに数えていると、3剤を組み合わせたときに気づかないまま超える。

資材を選ぶ一覧には「3/4回」のように出て、本剤の上限に達したもの・成分の通算が尽きたものは赤くなる。選んだあとは本剤・成分・作用機構の回数が並ぶ。履歴の「使用回数」タブでは棟ごとに一覧できる。

数え方の決まり：

- 散布記録の「棟・区画」は「1号棟、2号棟」のように複数入るので、分解して棟ごとに数える
- 複数の棟をまとめて回るときは、**いちばん使っている棟に合わせる**（超えている棟を見落とさないため）
- 状態が「取消」「予定」の記録は数えない
- 農薬登録のない資材（肥料）は数えない

### 数えきれないもの

- **灌注・定植時処理**：アクタラのチアメトキサム4回には定植時までの処理1回が、ベネビアODのシアントラニリプロール5回には株元灌注が含まれる。アプリは散布記録しか持たないので、灌注を記録していなければ通算は少なく出る
- **ウララDF**：散布3回と常温煙霧3回が別枠だが、アプリは区別していない
- **登録内容が確認できていない剤**：スミチオン乳剤（同名でもトマト適用のある製品とない製品がある）、フーモン（適用表にトマトの行がない）、トリフミン水和剤（本剤の回数がメーカー公式で3回、登録情報で5回と食い違う）は、確認できるまで回数を空にして数えない扱いにしてある

## 0-1. 生育調査を追加したとき（2026-08-04）

週1回の生育調査（茎径・生長点〜開花花房距離・開花段位・草丈と、目視での草勢確認）を株ごとに記録できるようにした。反映するには：

1. Apps Scriptエディタで最新の `gas/Code.gs` に貼り替えて保存
2. **`setup` を実行**（「生育調査」「生育調査明細」シートが追加される）
3. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「**新バージョン**」→ デプロイ

記録できる項目（株ごと）：

| まとまり | 項目 |
|---|---|
| 基本（毎回） | 茎径・生長点〜開花花房距離・草丈 |
| 数える項目 | 開花段位・収穫段位・花房下の葉数・着果数・葉数 |
| 実測（時間があるとき／折りたたみ） | 節間長・葉長・果径 |
| 障害果（折りたたみ） | 尻腐れ・裂果・その他の果数とメモ |
| 目視での草勢確認 | 成長点の形・葉の角度・葉の色・花房 |

「基本」と「数える項目」は常に表示し、手間のかかる実測と障害果は畳んである。**障害果の「0個」は0として保存される**（0だった週と、そもそも数えなかった週を区別するため）。

測定項目と目安値の根拠：
- 茎径は**生長点から15cm下**を測る。目安10mm前後（神奈川県「作物成育の見える化と管理法の改善【トマト入門編】」）。熊本県農業研究センターの検証では、生長点から12〜18cmの範囲で位置を統一すればばらつきが小さいと報告されている
- 生長点〜開花花房の距離は目安15cm前後。岩手県の資料では開花花房下の茎周30mm（＝直径約10mm）が目標値とされ、神奈川県の値とおおむね整合する
- **花房下の葉数**は摘葉のタイミング判断に使う（適正12枚・岩手県）
- **開花段位と収穫段位の差**は草勢が続くかの判断に使う（6段が目安・岩手県）。画面で差を自動計算し、4〜8段から外れたら色が変わる
- 週1回・中庸な株を最低4株（岩手県は8株が望ましいとする）
- ⚠️ これらは**大玉トマトの目安**。中玉（フルティカ等）固有の基準値は公的資料に見当たらないため、自分で測って基準を作っていく前提

`action=lastGrowth` で同じ場所の前回調査を引き、入力画面に前回値と増減を表示している。株ラベル（A〜D等）を毎回そろえると同じ株の推移が追える。

## 0. 既にセットアップ済みの場合（散布記録への統合）

葉面散布（液体肥料・微量要素等）も記録できるようにするため、**「防除記録」を「散布記録」に改称・拡張**した。1回の散布＝1記録で、タンクに混ぜた資材（農薬・展着剤・葉面散布肥料）を明細として並べる形になる。既存のスプレッドシートに反映するには：

1. Apps Scriptエディタで最新の `gas/Code.gs` の内容に貼り替えて保存
2. 関数選択で **`migrateToSpray` を選んで実行**する（シート名が改称される。防除記録→散布記録、マスタ_農薬→マスタ_資材 など）
3. 続けて **`setup` を実行**する（新しい列とシート「マスタ_散布目的」が追加される）
4. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「**新バージョン**」→ デプロイ
5. 「4. GitHub Pagesでの公開」の手順でフロントエンド一式を再度pushする

主な変更点：
- 散布記録に**目的**（マスタから複数選択＋自由入力）と**開始・終了時刻**を追加
- 明細に**区分**と**農薬登録の有無**を追加。保存時点のマスタ値をコピーして固定するので、後からマスタを直しても過去の記録の帳簿抽出結果は変わらない
- **作業分類から「防除」を外した**（散布は散布記録側で扱う）。ただし履歴やホームの一覧には散布記録も混ざって表示されるので、その日の作業として見える
- `action=legalLedger` で**農薬登録のある資材だけ**を抽出できる（法定帳簿への転記用。展着剤は農薬登録があるので含まれ、肥料は除外される）

## 1. スプレッドシートとGASの準備

1. Googleドライブで新しいスプレッドシートを作成する（例：「栽培管理DB」）
2. メニュー「拡張機能」→「Apps Script」を開く
3. デフォルトの `コード.gs` の中身を全部消して、`gas/Code.gs` の内容を貼り付けて保存
4. エディタ上部の関数選択で `setup` を選び、実行ボタン（▷）を押す
   - 初回は権限の承認画面が出るので許可する
   - 実行後、スプレッドシートに11枚のシート（作業記録／散布記録／散布記録明細／マスタ_拠点棟／マスタ_作業分類／マスタ_資材／マスタ_品目／マスタ_散布目的／マスタ_散布レシピ／マスタ_散布レシピ明細／気象データ）が作られ、マスタに初期データが入る
5. 「デプロイ」→「新しいデプロイ」→ 種類の選択で「ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - 「デプロイ」を押す
6. 発行された `…/exec` で終わるURLをコピーする

## 2. フロントエンドの設定

1. `frontend/config.js` を開き、`GAS_URL` に手順1-6でコピーしたURLを貼る
   ```js
   const CONFIG = {
     GAS_URL: "https://script.google.com/macros/s/XXXXXXXX/exec",
     APP_TOKEN: "",
   };
   ```
2. `GAS_URL` が空のままだとブラウザのlocalStorageだけで動く「お試しモード」になる（動作確認用）

## 3. マスタデータの調整

スプレッドシートの各マスタシートを直接編集して運用する（アプリ側に管理画面は作っていない）。

- **マスタ_拠点棟**：拠点・棟が増えたら行を追加。使わなくなったら「有効フラグ」をFALSEにする（削除しなくてよい）
- **マスタ_作業分類**：作業の種類を増減。散布に関わるものは散布記録側で扱うため置いていない
- **マスタ_資材**：使う資材（農薬・展着剤・葉面散布肥料）が増えたら追加。`10_Tomato/03_知識・ノウハウ/病害虫/農薬・防除メモ.md` を随時反映する
  - **区分**：殺虫剤／殺菌剤／展着剤／葉面散布肥料 など。散布記録の「散布区分（防除／葉面散布）」の自動判定に使う。展着剤は判定に影響させない
  - **農薬登録の有無**：法定帳簿に載せる対象かどうかの判定に使う。**区分では判定できない**点に注意（例：ドライバーは展着剤だが農薬登録があるため帳簿の対象、クロロゲン青は肥料登録なので対象外）
  - **必要な保護具**：ラベル記載の内容を参考に入力（一般的な目安であり、実際の使用前は必ずラベル・登録情報を確認する）。農薬登録がある資材を選んだときだけ画面に警告が出る
  - **本剤の使用回数**：その製品をその作で何回まで使えるか。数字だけを入れる（例 `3`）。害虫・病害ごとに違う場合は合計のほうを入れ、内訳はPHI目安に文章で残す
  - **成分と通算回数**：`成分名:回数` の形で、混合剤は `/` で区切る（例 `メタラキシルM:5/TPN:6`）。**別の製品でも同じ成分なら足される**制限で、TPNを含むフォリオゴールド・アミスターオプティフロアブル・ダコニール1000はどれを使ってもTPNとして通算6回以内になる。剤ごとに数えていては超過に気づけないので、この列が実質の要
  - **IRACコード／FRACコード**：コードだけを入れる（例 `4A`、混合剤は `11/M5`）。同じコードを続けると効かなくなるため、作用機構が偏っていないかを見るのに使う。分類対象外の剤（展着剤・肥料・気門封鎖剤）や、作用機構が不明なグループ（IRAC UN）は空にする
  - 回数とコードの列は、**空欄が「制限なし」ではなく「数えない」**の意味になる。登録内容を確認できていないものは空のままにしておく
- **マスタ_拠点棟の「現作の開始日」**：使用回数を「その作で何回目か」で数えるための区切り（`2026-09-01` の形式）。定植のたびに書き換える。空なら全期間を数える
- **マスタ_品目**：栽培する品目・品種を追加
- **マスタ_散布目的**：散布記録の目的チップになる。`分類`が「防除」なら病害虫の行、それ以外は生育・生理の行に並ぶ。**目的名に「、」は使えない**（目的タグの区切り文字のため）
- **マスタ_散布レシピ／マスタ_散布レシピ明細**：よく使う処方（どの資材をどの倍率で使うか）を事前登録しておくと、散布記録の入力画面でレシピを選ぶだけで資材リストが自動入力される。レシピ明細の「薬剤名」はマスタ_資材の薬剤名と一致させておくと、区分・農薬登録・保護具が連動する

編集後、アプリのホーム画面で「🔄 マスタを取り直す」を押すと反映される。マスタは端末に1時間キャッシュされていて、その間は問い合わせに行かないため、押さずに待つ場合は最大1時間かかる。

### 新しい薬剤を足すとき

「マスタ_資材」に1行足すだけでよい。`frontend/masters-default.js` と `gas/Code.gs` の初期データは、シートを作り直したときとお試しモードのためのものなので、実運用で追いかける必要はない。

最低限、薬剤ID（連番）・薬剤名・区分・調製単位（`mL` か `g`）・農薬登録の有無・有効フラグを埋めれば動く。**区分は上に挙げた語と一字一句合っていないと散布区分が「その他」に落ちる**ので、「殺虫剤（くん煙剤）」のような独自の書き方はしない（剤型の特殊さは希釈倍率目安や備考に書く）。倍率候補と成分の通算は `/` 区切りで、カンマを使うとスプレッドシートが桁区切りの数値と解釈して `2000,4000` が `20004000` になる。

成分の通算回数とIRAC/FRACコードは農薬登録情報提供システム（pesticide.maff.go.jp）のラベルを見ないと分からない。分からないまま埋めず、空にしておく。

### あとから列が増えたとき

機能追加でマスタの列が増えることがある。その場合はApps Scriptエディタで `setup` をもう一度実行する。既存シートの末尾に不足列だけが追加され、中身は消えない（`ensureSheet_` が不足分だけを足す作り）。ウェブアプリのデプロイを更新し直す必要はない。

**2027年1月から農政センターのハウス1棟を使う場合**：マスタ_拠点棟の「農政センター｜ハウス1棟」行の「有効フラグ」をTRUEに変更する。

## 6-2. マスタの書き込み窓口について

`doPost` に `type: "upsertMaster"` を用意してある。マスタ（拠点棟・作業分類・資材・品目・散布目的・散布レシピ・レシピ明細）の行を、スプレッドシートを手で開かずに追加・更新するための窓口。記録系シート（作業記録・散布記録）は対象外にしてある。

```
POST（Content-Type: text/plain）
{
  "type": "upsertMaster",
  "sheet": "マスタ_資材",
  "key": "薬剤ID",              // 複数列で照合するなら ["レシピID", "表示順"] のように配列
  "rows": [ { "薬剤ID": "P04", "薬剤名": "...", ... } ]
}
```

`key` が一致する行があれば渡した列だけ上書きし、なければ新しい行として追加する。渡さなかった列は既存の値のまま残る。

⚠️ この窓口は公開URLから叩けるため、`APP_TOKEN`（手順6）を設定していない状態では、URLを知っている人がマスタを書き換えられる。GitHubの公開リポジトリに `config.js` ごとURLが載っているので、気になる場合は手順6のトークン設定を先に済ませること。

## 7. 気象データの自動更新（天候・気温の自動取得）

作業記録・散布記録には天候・気温を手入力する欄を作っておらず、代わりに「気象データ」シートに日付ごとの最高・最低気温と天気概況を自動保存し、履歴画面でその日の記録とあわせて表示する。取得地点は千葉市緑区の代表座標で固定している（`gas/Code.gs` の `WEATHER_LAT`/`WEATHER_LON`）。

1. Apps Scriptエディタで関数選択から `setupWeatherTrigger` を選び、実行ボタン（▷）を押す（setup実行後に1回だけでよい）
2. これで「毎日朝5時に自動更新」のトリガーが登録され、実行と同時に当日分もすぐ取得される
3. 仕組み：Open-Meteo（無料・APIキー不要）から当日の予報値と前日分の実況に近い値をまとめて取得し、当日は「予報」、前日は「実績」として気象データシートに保存する。前日分は翌日のトリガー実行時に実績値へ自動更新される
4. 注意：ここでの「実績」はモデルの解析値ベースで、気象庁の観測実況そのものではないが、翌日更新の用途としては十分な精度として扱っている

## 動作確認のポイント

- 資材名・希釈倍数（or使用量）を空欄で散布記録を送信し、エラーになることを確認する
- 散布記録で複数の資材をリストに追加してから送信し、1回の記録として保存されることを確認する
- **農薬だけ／肥料だけ／混合の3パターン**を登録し、散布区分が「防除」「葉面散布」「防除・葉面散布」と正しく判定されることを確認する
- 保護具の警告が、農薬登録のある資材を選んだときだけ出ることを確認する（クロロゲン青では出ない）
- 目的をチップで複数選び、自由入力も併記して保存 → 履歴の「目的でしぼる」で両方から拾えることを確認する
- 散布レシピを選ぶと資材リストが自動入力されることを確認する
- `action=legalLedger` で農薬登録のある資材だけが抽出され、クロロゲン（青）が除外されることを確認する
- Android PWAとPCブラウザの両方から記録・履歴を確認し、同じデータが見えることを確認する（データ共有の確認）
- 機内モードでフォーム送信 → 「保留しました」の表示 → オンラインに戻すと自動送信されることを確認する（送信キューの確認）
- 履歴画面で、日付ごとに気象データ（最高・最低気温・天気）が表示されることを確認する
